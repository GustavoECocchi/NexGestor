## Achado novo — fonte parcialmente associada ainda aceita (P1)

Local: `app/service/benchmark_service.py`, `_localizar_fonte_associada`,
linhas 524–550 no HEAD analisado.

A função calcula cobertura integral usando TODOS os segmentos que tocam
o número. Só depois elimina índices/chunks inválidos para selecionar a
URL. Assim, segmentos sem fonte válida completam artificialmente a
cobertura de uma fonte que sustenta apenas parte do valor.

Reprodução sem rede, com objetos reais do SDK e helper existente da suíte:

```python
from test_benchmark_mercado import _resposta
from app.service.benchmark_service import _interpretar_resposta

for indices in ([], [99], [1]):
    resposta = _resposta(
        ["VALOR: 12.34"],
        supports=[(0, 7, 8, [0]), (0, 8, 12, indices)],
        chunks=["https://fonte.example/relatorio", None],
    )
    resultado = _interpretar_resposta("ctr_link", resposta)
    print(resultado.encontrado, resultado.value, resultado.fonte_url)
```

Nos três casos: `True`, `12.34`, `https://fonte.example/relatorio`.
A única fonte válida cobre `[7,8)`, um byte dos cinco de `12.34`.
O restante tem lista vazia, índice inexistente ou chunk sem web.
Esperado: rejeição como `BenchmarkFalhaTransitoria`.

Impacto: referência aparentemente verificada pode ter sustentação parcial;
o score não é afetado pelo desenho informativo. Não se demonstrou frequência
desse formato no Gemini real nem exploração em produção. A feature nasce
desligada, mas a invariável declarada está quebrada no código atual.

Correção recomendada: associar intervalos às fontes válidas antes de medir
cobertura, exigir cobertura integral da URL aceita e manter rejeição de
ambiguidade. Acrescentar as três regressões acima e revisar a versão do
cache para invalidar positivos aceitos pela regra defeituosa. Nenhuma
correção de produto foi executada neste pedido de análise.
